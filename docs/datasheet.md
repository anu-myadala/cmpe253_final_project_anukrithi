# Datasheet - HMDA California conventional home-purchase cohort used in the CMPE 253 project

_Generated by `src/make_docs.py` on 2026-11-22; structure follows Gebru et al. (2021). Facts from `config.yaml` and `results/`; judgement fields are the author's._

## Motivation
- Built for the CMPE 253 Track B project to measure fairness, privacy, explainability and robustness of mortgage-approval models on public data. Created by Anukrithi Myadala (SJSU); no funding.

## Composition
- Instances are loan applications (one row each) from the public HMDA Loan/Application Register, state = CA, action taken in {originated, denied}, loan purpose = home purchase, then filtered to loan_type in ['1'], occupancy_type in ['1'], lien_status in ['1'], reverse_mortgage in ['2'], open-end_line_of_credit in ['2'], business_or_commercial_purpose in ['2'], construction_method in ['1'], total_units in ['1', '2', '3', '4'].
- 2024: 174,655 applications (91.4 % originated); 2025: 165,198.
- Fields kept: 5 numeric and 7 categorical inputs, 4 sensitive attributes (evaluation only), 4 census-tract proxies (ablation only), lender id and county (privacy uniqueness check only).
- Label: y = 1 originated, 0 denied - the lender's decision, not ground-truth creditworthiness. No gold standard exists in the file.
- Missingness is logged per numeric input in `results/missingness_2024.csv`; DTI is reported by HMDA in bins (36-49 as integers), binned here with `prepare.bin_dti`.
- Sensitive content: protected-class fields are present by design of the public release; no direct identifiers (names, addresses) exist in the file.

## Collection process
- Downloaded from the CFPB/FFIEC HMDA Data Browser API (`https://ffiec.cfpb.gov/v2/data-browser-api/view/csv`) with filters {'loan_purposes': '1', 'actions_taken': '1,3'}; the API allows two filter criteria, so the remaining cohort rules run locally in `src/prepare.py`. Funnel counts per filter are in `results/funnel_2024.csv`.
- The data are self-reported by lenders under HMDA / Regulation C and published after CFPB disclosure modifications (some fields binned or redacted).

## Preprocessing / cleaning / labelling
- `src/prepare.py` applies the cohort filters, drops post-decision fields (17 fields in `leakage_drop`, including the two found by `src/leakage_audit.py`), converts numerics, bins DTI, builds `co_applicant_present`, keeps sensitive attributes as evaluation-only columns. Raw files are kept unmodified in `data/raw/`.

## Uses
- Used here for: baseline approval models, subgroup fairness evaluation, fairness interventions, SHAP explanations, robustness probes, membership-inference and DP experiments, 2024 -> 2025 drift.
- Should not be used for: any real lending decision; any claim about an individual lender's intent; inference about individual applicants.
